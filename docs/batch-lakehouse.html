Batch & Lakehouse Architecture

DeliveryFlow implements an open-table 3-tier Medallion Lakehouse architecture using Apache Iceberg, Project Nessie, MinIO S3, Apache Spark, and Apache Airflow to reliably compute, version, and publish operational SLA metrics and transportation cost KPIs.

Lakehouse Separation of Responsibilities

In a modern Lakehouse architecture, storage, table formatting, metadata cataloging, and compute are decoupled. DeliveryFlow maintains strict architectural isolation between these layers:

🗄
Storage: MinIO S3
High-performance S3-compatible object storage running locally in Docker. Holds the physical columnar Parquet data files, Iceberg metadata JSON files, and manifest lists inside the delivery-lakehouse bucket.
Bucket: delivery-lakehouse 9001
Δ
Table Format: Apache Iceberg
Open table format providing ACID transactional writes, hidden partitioning (pruning queries without exposing partition columns), schema evolution without rewriting data, and time-travel snapshots.
Format: Iceberg v2 ACID Parquet
🔗
Catalog: Project Nessie
Transactional REST catalog that provides Git-like branch, tag, and commit semantics over Iceberg table snapshots. Nessie stores its commit tree in PostgreSQL (nessie_metadata DB), guaranteeing multi-table ACID consistency.
REST API: Port 19120 Git-like Catalog
🔥
Compute: Apache Spark 3.5
Distributed computing runtime. Configured with the Iceberg Spark runtime extension (IcebergSparkSessionExtensions) and Nessie catalog integrations to read, transform, and commit data across all Medallion tiers.
Master UI: Port 8082 PySpark 3.5

The 3-Tier Medallion Data Architecture

DeliveryFlow organizes all Lakehouse tables into structured Medallion stages, progressively cleaning, enriching, and aggregating logistics data:

Medallion Tier Iceberg Table Partitioning Strategy Transformation Logic SLA / Consumer
Bronze (Raw) nessie.bronze.raw_delivery_events days(event_timestamp) Immutable append of operational delivery events from ClickHouse. Appends audit metadata: _ingested_at, _pipeline_run_id. Historical audits, replay jobs, machine learning model training.
Bronze (Raw) nessie.bronze.transportation_costs business_date Snapshot extraction from PostgreSQL public.transportation_costs. Preserves source row fidelity with ingestion audit stamps. Feed to Silver enrichment pipeline.
Silver (Enriched) nessie.silver.transportation_costs_enriched business_date Applies data quality validation. Computes row-level unit metrics: cost_variance, cost_per_km, cost_per_delivery, fuel_cost_pct, and vehicle_utilization_pct. Analytical ad-hoc queries & Gold aggregation stage.
Gold (Curated) nessie.gold.daily_delivery_kpi business_date, region Daily warehouse-level rollups: completion count, delayed delivery count, SLA on-time rate, average delay minutes, and fleet utilization ratio. Published to ClickHouse & Operations Dashboard.
Gold (Curated) nessie.gold.daily_transportation_cost_kpi business_date, warehouse_id Corridor route-level aggregations: total costs, planned vs. actual variance %, fuel expense share, duration variance, and risk score. Published to ClickHouse & Transportation Cost Dashboard.

Apache Airflow Orchestration & DAG Factory

Airflow coordinates all batch pipelines, managing scheduling, dependency ordering, source readiness checks, and post-execution validation:

⏱
DAG 1: delivery_daily_kpi
Schedule: @daily • File: dags/delivery_daily_kpi.py

Task Sequence:
  1. check_source_readiness: Executes a Python check against ClickHouse ensuring delivery.delivery_events contains rows for the period. Fails fast if no stream events exist.
  2. run_spark_daily_batch: Submits spark-submit /opt/deliveryflow/src/etl/apps/daily_kpi_job.py to compute Bronze and Gold tables and publish to ClickHouse.
Daily Operational SLA Production DAG
⏱
DAG 2: delivery_transportation_cost_daily_batch
Schedule: @daily • Factory: dags/batch_spark_dag_factory.py

Task Sequence:
  1. check_transport_cost_source: Verifies PostgreSQL public.transportation_costs has valid rows for the business date.
  2. run_transport_cost_spark_job: Submits transportation_cost_kpi_job.py to execute Bronze → Silver → Gold and ClickHouse publication.
  3. validate_transport_cost_output: Queries ClickHouse verifying that new Gold rows were successfully published.
Financial & Route Costs Metadata-Driven Factory

Data Quality Rules (QualityValidator)

Before transforming data, Spark applies automated data contract assertions defined in configs/datasets/delivery/transportation_costs.yaml:

  • Not-Null Rules: cost_id, business_date, delivery_id, route_id, vehicle_id, warehouse_id, region.
  • Non-Negative Rules: Distances, all cost components, fuel volume, and trip durations must be ≥ 0.
  • Accounting Equality Rule: actual_total_cost == fuel_cost + driver_cost + toll_cost + maintenance_cost + other_cost.
  • Referential Integrity: delivery_id must exist in delivery_plans; vehicle_id must exist in vehicles.

Batch Execution Runbook

Trigger and test batch lakehouse jobs using standard Makefile shortcuts:

bash — Batch Lakehouse Execution Commands
# 1. Run the daily delivery SLA batch job (default: daily-kpi)
make run-batch
# 2. Run the transportation cost batch job across Bronze, Silver, Gold
make run-batch DATASET=transportation-costs
# 3. Parameterize batch execution for a specific accounting business date
make run-batch DATASET=transportation-costs BATCH_DATE=2026-09-05
# 4. Run automated unit and integration tests for all batch components
make test-batch
