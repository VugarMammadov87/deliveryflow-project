Developer Onboarding & Operations Guide

This guide provides a comprehensive walkthrough for setting up, running, testing, and troubleshooting the DeliveryFlow data platform on a local workstation.

Prerequisites & Host Configuration

DeliveryFlow coordinates 12 distributed data infrastructure components within Docker. Verify that your development machine satisfies the following hardware and software requirements:

Requirement Minimum Specification Recommended Specification Verification Command
Operating System Windows 10/11 (WSL2), macOS 13+, or Ubuntu 22.04+ Linux x86_64 or Windows 11 with WSL2 Ubuntu uname -a or wsl --status
Memory (RAM) 8 GB dedicated to Docker 12 GB – 16 GB dedicated to Docker Check Docker Desktop Settings → Resources
Docker Engine Docker Engine 24.0+ & Compose v2.20+ Docker Engine 27.0+ & Compose v2.29+ docker compose version
GNU Make GNU Make 4.0+ (or run commands via bash/pwsh) GNU Make 4.3+ make --version
Python (Host) Python 3.10+ (for local pytest and scripting) Python 3.11+ with virtual environment python --version
Host Port Availability

Verify that the following local ports are not bound by existing host services: 5433 (Postgres Source), 5434 (Postgres Airflow), 8080 (Airflow Web), 8081 (Flink JobManager), 8088 (Superset UI), 8123 (ClickHouse HTTP), 8123 (ClickHouse HTTP), 9009 (ClickHouse Native), 9000 (MinIO S3 API), 9001 (MinIO Console), 9092 (Kafka Broker), and 19120 (Nessie Catalog API).

Step 1: Environment File Initialization

Clone the repository and create your local .env file from the provided template:

Bash / PowerShell 
# On Linux / macOS / Git Bash
cp .env.example .env

# On Windows PowerShell
Copy-Item .env.example .env

The table below summarizes the key environment variables configured in .env:

Variable Default Value Description
KAFKA_BOOTSTRAP_SERVERS kafka:9092 Internal Docker network address for Kafka KRaft broker
CLICKHOUSE_HOST clickhouse Host domain name for ClickHouse analytics database
MINIO_ROOT_USER admin S3 object store root access key
NESSIE_URI http://nessie:19120/api/v1 REST API endpoint for Apache Iceberg metadata catalog
POSTGRES_SOURCE_PORT 5433 Exposed host port for transactional source database
POSTGRES_AIRFLOW_PORT 5434 Exposed host port for Airflow orchestration metadata

Step 2: Build Container Images

In accordance with ADR-011, DeliveryFlow isolates runtime dependencies into two purpose-built Docker images:

  • deliveryflow-producer:latest: Lightweight image containing Python and kafka-python for synthetic event generation.
  • deliveryflow-tools:latest: Comprehensive platform tooling image containing PyIceberg, ClickHouse client, PySpark, psycopg2, and health check scripts.
Build Images 
# Build both container images
make build

# Or build individual images directly
make build-producer
make build-tools

Step 3: Start Platform Infrastructure

Launch the distributed stack in detached mode using Docker Compose:

Start Services 
make up

Step 4: Cluster Health Verification

Execute the automated multi-service health checker to verify that Kafka, ClickHouse, MinIO, Nessie, Spark, Airflow, Superset, and PostgreSQL instances are responsive and ready:

Health Check 
make health

Categorized Makefile Command Reference

The platform Makefile encapsulates complex Docker Compose and container execution commands into memorable, consistent targets:

1. Infrastructure & Lifecycle

Command Description Side Effects
make up Starts all infrastructure containers in background mode Spins up 12 Docker containers
make down Stops all active platform containers Preserves all database and object volumes
make build Builds both producer and platform tooling images Updates local Docker image cache
make restart Executes make down && make up Quick service reboot without data loss
make logs Streams unified Docker compose log output Attach to terminal with Ctrl+C to exit

2. Streaming & Event Ingestion

Command Description Configuration Parameters
make stream-demo Sends 30 delivery lifecycle events into Kafka TOPIC=delivery-events EVENTS=30
make fleet-demo Sends 120 vehicle telemetry events into Kafka TOPIC=vehicle-telemetry-events EVENTS=120
make stream-continuous Generates continuous event flow at 5 events/sec EVENTS=0 RATE=5 (Ctrl+C to stop)
make flink-submit Compiles and submits Java Flink jobs to cluster Deploys DataStream and SQL streaming jobs

3. Batch, Lakehouse & BI

Command Description Execution Target
make run-batch-kpi Executes Spark daily KPI aggregation job Submits PySpark job to spark-master
make dag-trigger Triggers delivery_daily_kpi DAG in Airflow Airflow scheduler container
make superset-import Imports dashboards, charts, and database connection Superset REST API at localhost:8088
make seed-postgres Re-seeds dimensional tables in PostgreSQL source Runs 003_create_source_tables.sh

4. Verification & Testing

Command Description Expected Outcome
make health Runs comprehensive health check across 8 endpoints Returns ALL SERVICES HEALTHY
make test Executes Python unit tests via pytest on host/tools Validates contracts, configs, and rate limiters
make e2e-test Runs end-to-end smoke test verifying pipeline flow Asserts row arrivals in ClickHouse and Iceberg

Teardown Operations & Data Safety

⚠ CRITICAL SAFETY: make clean vs. make purge

DeliveryFlow maintains a strict operational distinction between routine teardown and factory reset. Always understand the difference before executing maintenance commands:

Command Action Taken Data Volume Impact When to Use
make clean Stops and removes containers and network PRESERVED (Named volumes remain untouched) End of workday, rebooting machine, or updating code.
make purge Stops containers, deletes networks, and deletes named volumes DESTROYED (All tables, topics, Iceberg data, and MinIO objects are deleted) Corrupted database state, schema redesign, or complete factory reset.
Safe Teardown 
# Safe Teardown: preserves all data in Postgres, ClickHouse, MinIO, and Nessie
make clean

# Destructive Factory Reset: completely wipes all state
make purge

Local Development without Docker

You can test event contracts, platform configuration loaders, and synthetic generator rate logic on your host machine without starting Docker containers:

Host Testing 
# Create and activate virtual environment
python -m venv .venv
source .venv/bin/activate  # On Linux / macOS
# .venv\Scripts\Activate.ps1 # On Windows PowerShell

# Install test dependencies
pip install pytest jsonschema pyyaml pydantic

# Run unit tests
export PYTHONPATH="src"    # On Linux / macOS
# $env:PYTHONPATH="src"     # On Windows PowerShell
pytest tests/ -v
