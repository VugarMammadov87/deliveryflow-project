Core Architectural Decisions

Every technology in the DeliveryFlow platform was selected to solve specific production data engineering challenges:

∞
Stream-First Processing
Rather than relying on micro-batching, DeliveryFlow uses Apache Flink's native streaming runtime. This ensures exact-once semantics, sub-second latency from truck sensor to dashboard, and event-time watermarking for out-of-order logs.
Apache Flink 1.18 Explore Streaming →
Δ
Open Lakehouse with ACID
Apache Iceberg on MinIO provides full snapshot isolation, schema evolution without rewriting data, and partition hidden indexing. Project Nessie adds Git-like branching and transactional consistency across all Spark pipelines.
Apache Iceberg + Nessie Explore Lakehouse →
&zap;
Sub-Second Real-Time OLAP
ClickHouse serves as the operational analytical layer. Utilizing ReplacingMergeTree engines for automatic deduplication by event key and pre-calculated analytical views, analytical queries return in milliseconds.
ClickHouse 24.1 Explore Workflow →
📊
Declarative BI-as-Code
All 12 Superset charts, datasets, and 2 executive dashboards are defined declaratively in JSON/Python. Assets are checked into version control and deployed deterministically via automated CLI scripts.
Apache Superset 3.1 Explore Dashboards →

Platform Quick-Start Runbook

Start the entire local data platform using the bundled Makefile shortcuts:

bash — Local Platform Orchestration
# 1. Spin up all core infrastructure containers in detached mode
make up-d
# 2. Verify all 10 containers are healthy and ports are active
make status
# 3. Provision declarative Superset dashboards and ClickHouse connections
make import-superset-assets
# 4. Generate streaming events and run test batch DAG
make run-producer
