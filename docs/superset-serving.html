Superset BI Serving & Analytics

DeliveryFlow implements a production-grade BI-as-Code architecture using Apache Superset 3.1 connected directly to ClickHouse. All database connections, datasets, charts, and executive dashboards are defined declaratively in version control and provisioned automatically via Python scripts.

Declarative BI-as-Code Architecture

Traditional BI deployments suffer from manual click-driven drift, untracked metric edits, and broken staging-to-production promotions. DeliveryFlow completely eliminates manual dashboard creation by treating BI assets as first-class software code:

▶ Automated BI Provisioning Pipeline
Version Control Git Monorepo
Declarative YAML Spec
configs/superset/deliveryflow_bi.yaml defines all database targets, ClickHouse datasets, metric formulas, and dashboard layouts.
Fully peer-reviewed via pull requests.
Automation Python 3.10+
Provisioning Importer Engine
scripts/import_superset_assets.py authenticates against Superset REST APIs (JWT token) and synchronizes assets idempotently.
Triggered via make import-superset-assets.
Visualization Port 8088
Apache Superset Runtime
Serves interactive dashboards with native filters directly to logistics dispatchers and supply chain executives.
Direct SQL pushdown to ClickHouse.

Automated REST API Provisioning Steps

  1. Authentication: Authenticates against /api/v1/security/login using admin credentials to retrieve a short-lived Bearer JWT token.
  2. Database Registration: Checks /api/v1/database/ and ensures the ClickHouse database connection (clickhousedb://default:clickhouse@clickhouse:8123/delivery) is created.
  3. Dataset Synchronization: Calls /api/v1/dataset/ to inspect and register the 6 ClickHouse analytical views, defining temporal columns (e.g. business_date, event_hour) and adhoc column types.
  4. Chart Generation: Posts chart slices to /api/v1/chart/ with visualization params (bar, line, table, big number), metric aggregations, and layout coordinates.
  5. Dashboard Layout & Filter Binding: Constructs the dashboard shell at /api/v1/dashboard/, calculates responsive grid position coordinates, attaches chart IDs, and binds native multi-select filter components.

Dashboard 1: DeliveryFlow Operations Dashboard

Dashboard Title: DeliveryFlow Operations Dashboard • Slug: deliveryflow-operations
Designed for real-time dispatchers, route coordinators, and warehouse fulfillment leads. It reflects active operational events streamed via Apache Flink into ClickHouse.

▣
1. Delivery Status Overview
Type: Distribution Bar Chart (dist_bar)
Dataset: v_delivery_status_overview
Metrics: event_count • Group By: status

Displays the distribution of shipments across lifecycle states (PENDING, IN_TRANSIT, DELIVERED, DELAYED).
Real-Time State Operational Status
📊
2. Delay by Region & Service Level
Type: Pivot Table v2 (pivot_table_v2)
Dataset: v_delay_by_region
Metrics: delay_rate, avg_delay_minutes
Rows: region • Columns: service_level

Cross-tabulates delay percentage and average minutes late across regions and SLA tiers (standard, express, same-day).
SLA Compliance Delay Matrix
🚚
3. Vehicle Utilization
Type: Interactive Data Table (table)
Dataset: v_vehicle_utilization
Metrics: avg_utilization_ratio
Group By: vehicle_id, active_status, route_id

Tracks fleet transport capacity deployment, alerting dispatchers to underloaded vans or overloaded trucks.
Fleet Optimization Capacity Ratio
📈
4. Hourly Delivery Event Volume
Type: Time-Series Line (echarts_timeseries_line)
Dataset: v_delivery_event_volume
Metrics: event_count • Time Grain: 1 Hour (PT1H)
Group By: event_type

Visualizes throughput volume peaks throughout the workday to identify dispatch rush hours.
Throughput Trends Hourly Volume
🏢
5. Warehouse Daily KPI
Type: Analytical Table (table)
Dataset: v_warehouse_daily_kpi
Metrics: completed_deliveries, delayed_deliveries, on_time_rate, total_order_value
Group By: business_date, region, warehouse_id

Daily scorecard evaluating individual warehouse dispatch efficiency and order value fulfillment.
Facility Scorecard Daily Warehouse Rollup

Native Dashboard Filter Bar

Dashboard 2 includes 4 native multi-select filter components that filter all 7 charts in real time:

  • Business Date: Temporal filter (filter_time) scoping the accounting window.
  • Warehouse: Multi-select filter (filter_select) filtering by originating distribution center.
  • Region: Multi-select filter (filter_select) filtering by geographic operating area.
  • Route: Multi-select filter (filter_select) isolating specific transit corridors.

Operator Runbook & Live UI Access

Manage and provision Superset assets locally using automated Make commands:

bash — Superset BI Provisioning
# 1. Provision or refresh both dashboards, 6 datasets, and 12 charts via Superset REST API
make import-superset-assets
# 2. Run automated test assertions to verify all BI asset specs
pytest tests/test_superset_transportation_cost_assets.py
Access Apache Superset Web UI
Open your browser and navigate to:
  • URL: http://localhost:8088
  • Username: admin
  • Password: admin
  • Dashboards Menu: Browse to DeliveryFlow Operations Dashboard or Transportation Cost & Route Performance.
