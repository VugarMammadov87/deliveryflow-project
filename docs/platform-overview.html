Platform Overview & Architecture

DeliveryFlow is a local modern data platform engineered to solve real-world operational and analytical logistics challenges. It demonstrates how modern data engineering bridges low-latency event processing with large-scale Lakehouse storage without incurring cloud infrastructure costs.

The Logistics Business Problem

In freight, e-commerce, and last-mile logistics, delivery operations suffer from two opposing operational demands:

  • Immediate Operational Awareness (Seconds to Minutes): Dispatchers and customer support need to know where a parcel is right now, whether a truck is experiencing highway delays, if engine temperature has spiked, or if fuel is running dangerously low. This requires continuous real-time streaming pipelines.
  • Strategic & Financial Analytics (Daily to Multi-Year): Logistics executives and supply chain managers need to evaluate daily carrier SLA compliance, warehouse dispatch bottlenecks, regional delay trends, vehicle fleet fuel efficiency, route profitability, and transportation cost variances. This requires historical batch Lakehouse computation.
The Dual-Engine Approach
DeliveryFlow addresses this by pairing Apache Flink for continuous real-time state tracking with Apache Spark + Apache Iceberg for robust historical batch analytics, unified through ClickHouse as a high-speed analytical serving layer.

Dual Pipeline Architecture

The platform routes data through two complementary paths running side by side:

▶ Operational Streaming vs. Analytical Lakehouse Paths
Path A: Real-Time < 1s Latency
Operational Streaming Path
Kafka → Flink DataStream & SQL → ClickHouse ReplacingMergeTree
Sub-second event ingestion, schema validation, live deduplication, and active operational delay monitoring.
Path B: Batch Lakehouse Daily Scheduled
Analytical Lakehouse Path
Airflow → Spark Batch Jobs → Iceberg (Bronze/Silver/Gold) → ClickHouse Serving
Snapshot isolation, ACID transactions on MinIO with Nessie, route cost variance calculations, and long-term trend analysis.

Technology Stack Deep Dive

Every technology in DeliveryFlow was chosen to reflect production enterprise standards while remaining lightweight enough to run reliably on a developer laptop:

Acts as the distributed, persistent message log. Runs in KRaft mode (no ZooKeeper dependency), decoupling event producers from downstream stream consumers. Provides strict partition ordering by delivery_id and vehicle_id.

End-to-End Delivery Lifecycle Walkthrough

Follow a delivery order from initial creation through the entire platform:

  1. Order Placement & Seed: The producer generates a delivery order and writes reference data (customer, warehouse, order value) to PostgreSQL logistics_source.
  2. Event Publication: As the delivery progresses, the producer emits lifecycle events (ORDER_LOADED, VEHICLE_DEPARTED, IN_TRANSIT, DELIVERY_DELAYED, DELIVERED) to Kafka delivery-events keyed by delivery_id.
  3. Stream Consumption: Flink's DeliveryStreamingJob validates the JSON schema contract, maintains event ordering, and streams updates via HTTP to ClickHouse.
  4. Serving Projection: ClickHouse updates delivery.delivery_current_state and appends to delivery.delivery_events.
  5. Live Operational Dashboard: Superset queries prepared analytical views in ClickHouse to show real-time status and active delays.
  6. Daily Lakehouse Batch: At midnight, Airflow triggers Spark's daily_kpi_job.py and transportation_cost_kpi_job.py. Spark aggregates performance metrics, commits Bronze/Silver/Gold Iceberg tables to MinIO via Nessie, and publishes daily KPI snapshots back to ClickHouse.
