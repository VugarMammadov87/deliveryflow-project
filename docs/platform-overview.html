Platform Overview

DeliveryFlow is a local modern data platform designed to solve operational and analytical logistics challenges. It demonstrates how modern data engineering bridges low-latency event processing with large-scale Lakehouse storage without incurring cloud infrastructure costs.

The Logistics Business Problem

In freight, e-commerce, and last-mile logistics, delivery operations suffer from two opposing operational demands:

  1. Immediate Operational Awareness (Seconds to Minutes): Dispatchers and customer support need to know where a parcel is right now, whether a truck is experiencing delays, if engine temperature has spiked, or if fuel is running dangerously low. This requires real-time streaming pipelines.
  2. Strategic & Financial Analytics (Daily to Multi-Year): Logistics executives and supply chain managers need to evaluate daily carrier SLA compliance, warehouse dispatch bottlenecks, regional delay trends, vehicle fleet fuel efficiency, and route optimization. This requires historical batch Lakehouse computation.
The Dual-Engine Approach

DeliveryFlow addresses this by pairing Apache Flink for continuous real-time state tracking with Apache Spark + Apache Iceberg for robust historical batch analytics, unified through ClickHouse as a high-speed analytical serving layer.

Dual Pipeline Architecture

The platform routes data through two complementary paths:

Operational Streaming
Flink DataStream & Flink SQL
Sub-second event ingestion, schema validation, and current-state materialization in ClickHouse.
&
Analytical Lakehouse
Airflow + Spark + Iceberg
Daily scheduled KPI computation, ACID commits to MinIO via Nessie, and publishing back to ClickHouse.

Technology Stack Deep Dive

Every technology in DeliveryFlow was chosen to reflect production standards while remaining lightweight enough to run reliably on a developer laptop:

Apache Kafka (KRaft)

Transport
Event Streaming Backbone

Acts as the distributed, persistent message log. Runs in KRaft mode (no ZooKeeper dependency), decoupling event producers from downstream stream consumers.

Topics: delivery-events, vehicle-telemetry-events Port: 9092

Apache Flink

Stream Compute
Stateful Stream Processing

Provides event-time processing, watermark tracking, and tumbling window aggregations. Runs both DataStream API for delivery orders and Table API/SQL for fleet telemetry.

Jobs: DeliveryStreamingJob, VehicleTelemetrySqlJob Web UI: Port 8081

ClickHouse

Serving Layer
Real-Time OLAP Database

Columnar database optimized for analytical aggregations and instant dashboard queries. Uses ReplacingMergeTree for deduplicated latest-state records and MergeTree for event logs.

Databases: delivery, fleet Ports: 8123 (HTTP), 9009 (Native)

Apache Spark

Batch Compute
Distributed Batch & Lakehouse ETL

Executes daily enriched KPI aggregations, reads source operational facts via JDBC, and writes versioned Parquet data to Iceberg tables.

Master UI: Port 8082 Application: daily_kpi_job.py

Apache Iceberg & Nessie

Lakehouse
Open Table Format & Catalog

Iceberg provides schema evolution, hidden partitioning, and ACID transactions. Nessie acts as the transactional catalog with git-like branch and commit semantics.

Warehouse: s3://delivery-lakehouse/warehouse Catalog URI: Port 19120

MinIO Object Storage

Storage
Local S3-Compatible Storage

Stores the physical Parquet data files, metadata JSONs, manifest lists, and manifest files created by Iceberg transactions.

Console UI: Port 9001 API Port: 9000

Apache Airflow

Orchestration
Workflow Scheduler & Control Plane

Coordinates scheduled batch pipelines. Verifies ClickHouse source readiness before submitting Spark container execution.

DAG: delivery_daily_kpi Webserver UI: Port 8080

Apache Superset

BI & Analytics
BI-as-Code Dashboard Engine

Provides operational delivery performance charts and regional KPIs. Entirely provisioned via declarative YAML configuration.

Web UI: Port 8088 Config: deliveryflow_bi.yaml

End-to-End Delivery Lifecycle

Follow a delivery order from initial creation through the entire platform:

  1. Order Placement & Seed: The producer generates a delivery order and writes reference data (customer, warehouse, order value) to PostgreSQL logistics_source.
  2. Event Publication: As the delivery progresses, the producer emits lifecycle events (ORDER_LOADED, VEHICLE_DEPARTED, IN_TRANSIT, DELIVERY_DELAYED, DELIVERED) to Kafka delivery-events keyed by delivery_id.
  3. Stream Consumption: Flink's DeliveryStreamingJob validates the JSON schema contract, maintains event ordering, and streams updates via HTTP to ClickHouse.
  4. Serving Projection: ClickHouse updates delivery.delivery_current_state and appends to delivery.delivery_events.
  5. Live Operational Dashboard: Superset queries prepared analytical views in ClickHouse to show real-time status and active delays.
  6. Daily Lakehouse Batch: At midnight, Airflow triggers Spark's daily_kpi_job.py. Spark reads the day's event facts from ClickHouse, aggregates performance metrics, commits Bronze/Gold Iceberg tables to MinIO via Nessie, and writes daily KPI snapshots back to ClickHouse.
