PostgreSQL Relational Source Tables

The operational source of truth is stored in PostgreSQL (logistics_source database on port 5433). It maintains enterprise relational integrity across 7 core logistics entities:

1. warehouses

Physical fulfillment centers and regional distribution hubs.

Column Type Constraint Nullable Description
warehouse_id TEXT PRIMARY KEY NO Unique warehouse identifier (e.g. WH-001)
warehouse_name TEXT — NO Human-readable warehouse facility name
region TEXT — NO Operating geographic region (e.g. Baku-North, Absheron)
city TEXT — NO City location of the logistics hub
latitude NUMERIC(9,6) — NO Geographic latitude coordinate
longitude NUMERIC(9,6) — NO Geographic longitude coordinate
created_at TIMESTAMPTZ DEFAULT now() NO Timestamp when warehouse record was registered

2. vehicles

Physical fleet transport vehicles operating logistics delivery routes.

Column Type Constraint Nullable Description
vehicle_id TEXT PRIMARY KEY NO Unique vehicle identification code (e.g. VEH-101)
plate_number TEXT UNIQUE NO Government vehicle registration plate
vehicle_type TEXT — NO Classification: van, truck, sprinter
capacity_total NUMERIC(12,2) CHECK (> 0) NO Maximum package cargo carrying capacity
active BOOLEAN DEFAULT true NO Operational flag for active duty deployment
created_at TIMESTAMPTZ DEFAULT now() NO Timestamp vehicle was onboarded to the fleet

3. drivers

Certified delivery personnel responsible for executing shipments.

Column Type Constraint Nullable Description
driver_id TEXT PRIMARY KEY NO Unique employee ID (e.g. DRV-501)
full_name TEXT — NO Full legal name of the driver
phone_number TEXT — YES Contact telephone number for dispatch support
active BOOLEAN DEFAULT true NO Current employment and availability status
created_at TIMESTAMPTZ DEFAULT now() NO Driver onboarding registration timestamp

4. customer_orders

Commercial orders submitted by customers requiring freight or parcel transport.

Column Type Constraint Nullable Description
order_id TEXT PRIMARY KEY NO Commercial order reference identifier
customer_id TEXT — YES Customer account or profile identifier
customer_region TEXT — NO Target delivery destination region
destination_city TEXT — YES Target city for final delivery handover
destination_latitude NUMERIC(9,6) — NO Destination delivery latitude coordinate
destination_longitude NUMERIC(9,6) — NO Destination delivery longitude coordinate
service_level TEXT DEFAULT 'standard' NO SLA Tier: standard, express, same_day
priority TEXT DEFAULT 'normal' NO Priority ranking: low, normal, high, urgent
package_count INTEGER CHECK (> 0) NO Number of physical parcel units in order
order_value NUMERIC(12,2) CHECK (>= 0) NO Monetary declared order valuation (AZN / USD)
payment_method TEXT DEFAULT 'card' NO Billing method: card, cash, corporate_invoice
order_created_at TIMESTAMPTZ — NO Timestamp order was created by customer
promised_delivery_at TIMESTAMPTZ — NO Customer SLA committed delivery deadline
created_at TIMESTAMPTZ DEFAULT now() NO Database record ingestion timestamp

5. shipments

Logistics packaging unit linking customer orders to originating fulfillment warehouses.

Column Type Constraint Nullable Description
shipment_id TEXT PRIMARY KEY NO Unique shipment tracking code (e.g. SHP-9021)
order_id TEXT FK → customer_orders NO Associated customer order identifier
warehouse_id TEXT FK → warehouses NO Fulfillment facility handling dispatch
shipment_status TEXT — NO Lifecycle state: PENDING, PACKED, DISPATCHED
created_at TIMESTAMPTZ DEFAULT now() NO Shipment package record creation timestamp

6. delivery_plans

Scheduled dispatch plan assigning a shipment to a specific vehicle, driver, and transit corridor.

Column Type Constraint Nullable Description
delivery_id TEXT PRIMARY KEY NO Unique operational delivery transit ID (e.g. DEL-10492)
shipment_id TEXT FK → shipments NO Shipment package assigned to this transit
vehicle_id TEXT FK → vehicles NO Assigned transport vehicle unit
driver_id TEXT FK → drivers NO Assigned delivery driver
route_id TEXT — NO Designated logistics corridor (e.g. RT-BAKU-SUMQAYIT)
planned_departure_at TIMESTAMPTZ — NO Scheduled warehouse exit timestamp
planned_arrival_at TIMESTAMPTZ — NO Scheduled destination arrival timestamp
planned_distance_km NUMERIC(12,2) CHECK (>= 0) NO Estimated corridor transit distance in km
created_at TIMESTAMPTZ DEFAULT now() NO Plan scheduling timestamp

7. transportation_costs

Financial ledger records capturing cost breakdowns and fuel metrics for executed routes.

Column Type Constraint Nullable Description
cost_id TEXT PRIMARY KEY NO Unique financial ledger cost record identifier
business_date DATE — NO Accounting operating date of route execution
delivery_id TEXT FK → delivery_plans NO Associated operational delivery transit plan
route_id TEXT — NO Corridor code for cost allocation and benchmarking
vehicle_id TEXT FK → vehicles NO Vehicle unit incurring operating expenses
warehouse_id TEXT FK → warehouses NO Originating dispatch warehouse
region TEXT — NO Geographic territory for regional cost P&L
planned_distance_km NUMERIC(12,2) CHECK (>= 0) NO Budgeted route distance in kilometers
actual_distance_km NUMERIC(12,2) CHECK (>= 0) NO GPS odometer measured distance driven
planned_cost NUMERIC(12,2) CHECK (>= 0) NO Target operating budget allocated for route
fuel_cost NUMERIC(12,2) CHECK (>= 0) NO Direct diesel or gasoline expense incurred
driver_cost NUMERIC(12,2) CHECK (>= 0) NO Driver wage, overtime, and trip allowance
toll_cost NUMERIC(12,2) CHECK (>= 0) NO Highway and toll road transit charges
maintenance_cost NUMERIC(12,2) CHECK (>= 0) NO Vehicle wear-and-tear & servicing allocation
other_cost NUMERIC(12,2) CHECK (>= 0) NO Incidental parking, loading, and handling fees
actual_total_cost NUMERIC(12,2) CHECK (sum of parts) NO fuel + driver + toll + maintenance + other
fuel_liters NUMERIC(12,2) CHECK (>= 0) NO Total fuel volume consumed during trip
delivery_count INTEGER CHECK (>= 0) NO Total drops completed on this corridor
vehicle_capacity NUMERIC(12,2) CHECK (> 0) NO Max vehicle payload volume/package ceiling
used_capacity NUMERIC(12,2) CHECK (<= capacity) NO Actual cargo loaded during transit run
planned_duration_minutes INTEGER CHECK (>= 0) NO Estimated schedule duration from plan
actual_duration_minutes INTEGER CHECK (>= 0) NO Actual transit elapsed time from dispatch to end
created_at TIMESTAMPTZ DEFAULT now() NO Audit record creation timestamp
updated_at TIMESTAMPTZ DEFAULT now() NO Batch watermark timestamp for incremental ETL

Analytical Lakehouse Schema (Apache Iceberg)

DeliveryFlow organizes its historical analytical storage using the Medallion Architecture (Bronze, Silver, Gold) backed by Apache Iceberg, Project Nessie REST catalog, and MinIO S3 object storage (s3://delivery-lakehouse/warehouse/).

Lakehouse Layer Full Iceberg Identifier Partitioning Strategy Transformation Logic Primary Downstream Consumer
Bronze (Raw) nessie.bronze.raw_delivery_events days(event_timestamp) Raw append-only event stream from ClickHouse JDBC; appends _ingested_at and _pipeline_run_id. Historical audits, replay jobs, data scientists.
Bronze (Raw) nessie.bronze.transportation_costs business_date Raw operational snapshots extracted from Postgres transportation_costs. Silver layer ETL processing.
Silver (Cleaned) nessie.silver.transportation_costs_enriched business_date Calculates variance (actual - planned), unit economics (cost_per_km, cost_per_delivery), and capacity utilization. Gold KPI aggregations & ad-hoc analytics.
Gold (Curated) nessie.gold.daily_delivery_kpi business_date, region Aggregates completion count, SLA delay rate, on-time percentage, and average delay minutes by warehouse and date. ClickHouse publishing & executive reporting.
Gold (Curated) nessie.gold.daily_transportation_cost_kpi business_date, warehouse_id Corridor-level route financial aggregates: planned vs actual cost, fuel %, duration variance, and risk index. ClickHouse publishing & Superset Dashboard.

Real-Time OLAP Layer (ClickHouse)

ClickHouse acts as the high-speed analytical serving database, hosting 2 dedicated databases: delivery and fleet.

Database.Table / View Table Engine Partition Key Sorting / Deduplication Key TTL / Retention

delivery.vehicle_current_state ReplacingMergeTree(version) — vehicle_id Active state (Indefinite)
delivery.daily_delivery_kpi ReplacingMergeTree(version) toYYYYMM(business_date) (business_date, region, warehouse_id) Historical snapshot

fleet.vehicle_current_state ReplacingMergeTree(version) — vehicle_id Active state
